# Review Scope 三模式判定

## 三模式对照

| 模式 | 触发条件（任一满足即入） | 必交交付物 | 跳过的流程 |
|---|---|---|---|
| **full** | > 500 行；或涉及支付/权限/对账/对外 API/数据迁移；或已上线 ≥ 6 月的核心业务 | 项目画像 + 维度扫描 + 风险决策矩阵 + Top 10 + 6 月崩溃路径 | 无 |
| **standard** | 100-500 行；或不满足 nano 全条件但不达 full 任一 | 项目画像 + 维度扫描 + 风险决策矩阵 | Top 10、6 月崩溃路径 |
| **nano** | < 100 行 且 非认证/计费/安全/迁移关键词 且 12 月内无变更 且 无 `as any`/`ponytail` 等气味 | 5 字段速记表（维度/严重度/位置/影响/建议） | 上面 4 项 |

**判定时机**：Phase 0 末尾、项目画像报告最后一段。

## 判定的命令（启发式，手工可调，但调整须在画像报告里记录原因）

```bash
# 行数
wc -l <FILE>

# 12 月内变更频率
git log --since="12 months ago" --oneline -- <FILE> | wc -l

# 高敏关键词
grep -E "auth|payment|billing|permission|secret|migrate|ddl" <FILE>

# 气味关键词
grep -E "as any|ponytail|fire-and-forget|void.*\.catch" <FILE>
```

## 重要：跨模式恒定项

下列 **永远必走，与 scope 无关**：

- Phase 1 安全网（铁律 #2）
- 全部 8 条铁律
- 项目类型过滤后的维度扫描
- 自动修复前要求"确定性技术缺陷 + 单文件 ≤ 30 行 diff + 不涉禁区"三重门

## 升级规则（动态调整）

如果审查过程中发现新事实（如 nano 文件实际涉及 SSO token 校验），立即升至 standard 或 full，且补齐相应交付物。**降级不升模式 = 遗漏 = 报告作废**。

## 模式选择的话术（给用户）

> 该文件按行数与变更频率判定为 **standard** 模式（项目画像 + 维度扫描 + 风险决策矩阵）。如果您认为有遗漏，可升级到 **full** 模式（增加 Top 10 + 6 月崩溃路径，耗时约 X 分钟）。
