## 问题记录模板（每条发现必填 7 字段）

```
【维度】     — 对应 1-29，必须标号
【严重度】   — 阻塞/严重/一般/建议；过二次审视后写定
【问题描述】 — 一句话说清"现象 + 触发 + 结果"
【触发场景】 — 真实可达的输入序列（含时间、并发、外部依赖）
【位置】     — 文件:行（避免大段粘贴代码）
【影响分析】 — 业务影响 + 是否理论风险 + 是否有可达利用链
【回归风险】 — 修复可能破坏的功能（必填）
【修复建议】 — 自动修复 / 草案（草案必附下方三要素）
【验证方法】 — 测试用例思路 / 监控断言 / 人工步骤
```

### 修复草案的人工验证三要素（必附）

- [ ] **历史日志**：已通过历史日志验证该场景实际发生频率（标"零发生"/"X 次/月"）
- [ ] **隐性契约**：已检查所有调用方的隐性契约（接口文档/监控数据/老调用记录）
- [ ] **灰度方案**：已设计灰度验证方案（如仅对 5% 流量启用修复）

任意一项打勾但未行动 = 报告作废。

## 视角预设（启动阶段贴入意识）

- 所有外部输入（HTTP / DB 存量 / 配置文件 / 环境变量）都是恶意、脏的
- 流量、数据量、并发随时暴涨到当前 10 倍
- 所有第三方服务随时可能宕机、超时或返回异常
- **唯一懂这段代码的人已经离职**
- 用户会执行最反人类、最意外的操作序列

## 安全网启动清单（会话第 1 步）

无论本次会话是否计划修改源码，以下 3 步必走：

1. `git checkout -b pre-review-snapshot-$(date +%Y%m%d)` —— 与现分支分离
2. `git status --porcelain > /tmp/pre-review-unttracked.txt` —— 锁定未跟踪文件清单
3. 若无 Git：见下方"无 Git 仓库兜底"

之后才能进入维度扫描。

## 无 Git 仓库兜底

```bash
# 1. 判定确实不是 Git 仓
[ -d .git ] && echo "GIT_FOUND" || echo "NO_GIT"

# 2. 压缩关键目录（不含 node_modules 与 dist）
tar czf REVIEW-LOOP-$(date +%Y%m%d).tar.gz \
  src/ db/ docker-compose.yml .env.example package.json 2>/dev/null

# 3. SHA256 + 大小记录
sha256sum REVIEW-LOOP-$(date +%Y%m%d).tar.gz > /tmp/pre-review-backup.sha256
ls -lh REVIEW-LOOP-$(date +%Y%m%d).tar.gz >> /tmp/pre-review-backup.sha256

# 4. 将 sha256 输出原样贴入审计日志（Phase 1）
```

**兜底约束**：审查中若发现新事实需新文件（如临时分析脚本），停止审查，先补压缩并更新 sha256，再继续。
